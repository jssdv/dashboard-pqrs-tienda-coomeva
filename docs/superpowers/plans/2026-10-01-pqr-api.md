# PQR Summary API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Serve the existing dashboard summary over a local HTTP API without exposing personal case fields.

**Architecture:** `createSummaryServer` builds a `node:http` server and does not call `listen`. `GET /summary` loads cases through `CaseRepository.list()` and returns `summarize`. Every other method or path returns 404 JSON. The CLI opens SQLite and listens on `0.0.0.0` and `PORT` (default 3000).

**Tech Stack:** Node.js 20+, TypeScript 5, Vitest, `node:http`, `tsx`. No Express, Fastify, or new dependencies.

## Global Constraints

- Response body of `GET /summary` is exactly `DashboardSummary`. No cases endpoint.
- Names, emails, and free text never leave SQLite through this API.
- Unknown paths and non-GET methods return status 404 and body `{"error":"not found"}` with `Content-Type: application/json`.
- Listen address is `0.0.0.0`. Port is `process.env.PORT` or `3000`.
- Missing CLI argument exits with code 1 and stderr `usage: serveSummary <db.sqlite>`.
- No web UI and no holiday API in this plan.
- Work on branch `feature/pqr-core`. One commit per task. Do not push.

```ts
import { createServer, type Server } from "node:http";
import { summarize } from "../domain/summary.js";
import type { CaseRepository } from "../store/repository.js";

export function createSummaryServer(repository: CaseRepository): Server {
  return createServer((req, res) => {
    const url = new URL(req.url ?? "/", "http://127.0.0.1");
    if (req.method === "GET" && url.pathname === "/summary") {
      res.writeHead(200, { "Content-Type": "application/json" });
      res.end(JSON.stringify(summarize(repository.list())));
      return;
    }
    res.writeHead(404, { "Content-Type": "application/json" });
    res.end(JSON.stringify({ error: "not found" }));
  });
}
```
